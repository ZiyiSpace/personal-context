# X 发布与起号策略 v1

整理日期：2026-07-16

适用账号：以中文为主，围绕 AI Coding、Agent 工作流、AI 产品实践和个人成长进行公开记录的个人账号。

## 一句话结论

公众号文章可以进入 X，但不应该原样搬运。

对新账号更有效的路径是：

```text
一条能独立成立的短观点
-> 一组原生 Thread 把判断讲清楚
-> 需要时再发布 Premium 长帖／Article
-> 外部文章链接只承担补充阅读，不承担首轮传播
```

X 是“先参与公共对话，再获得主页访问”的平台。长文负责建立专业度，短帖和回复负责分发，两者缺一不可。

## 公众号长文能否直接发到 X

### 技术上可以

X 官方帮助中心当前说明：

- Premium 用户可以创建最长 25,000 字符的 Longer Post。
- Premium 用户可以使用 Articles 发布长篇书面内容，具体权益可能随套餐和地区变化。
- Longer Post 可以包含图片、GIF 或视频，但目前不能正常排期；网页端的草稿能力也有限。

《我被 Superpowers 的 token 消耗教育了一下》Markdown 源稿约 4,148 个字符，因此长度完全放得下。

### 传播上不建议原样贴

原稿直接复制到 X 会出现五个问题：

1. Markdown 表格无法保持公众号里的可读样式。
2. 本地图片路径不会变成 X 图片，必须重新上传。
3. 公众号标题和章节适合主动阅读，X 信息流更依赖前 1～3 句能否让人停下。
4. 原稿同时承担现场、解释、工具比较和参考资料，信息流里显得过重。
5. 对新账号而言，只发长文而不参与对话，文章很难获得第一批读者。

因此，正确动作不是“缩短全文”，而是让同一个核心判断产生不同的 X 原生成品。

## 这篇文章在 X 上的推荐产品组合

| 成品 | 作用 | 推荐程度 |
| --- | --- | --- |
| 单条短观点 | 测试钩子，获得第一轮讨论 | 必发 |
| 7 条 Thread | 完整讲清现场、四种工具和选择规则 | 主成品 |
| Premium 长帖 | 给不喜欢逐条展开的读者一次读完 | 可同步 |
| X Article | 作为个人主页里的长期文章资产 | 有 Premium 且准备长期经营时再发 |
| 公众号链接 | 承接微信读者或保存排版版全文 | 放末条回复，不放第一条 |

推荐发布顺序：先发 Thread。Thread 跑出真实反馈后，再决定是否同步长帖／Article，而不是四种格式同一天全部发完。

## X 写作的可验证规则

### 来自 X 官方的部分

X Business 对自然内容的建议包括：

- 每条只传递一个核心信息。
- 使用对话式语气，保持简洁。
- 图片、GIF 和视频可以帮助内容被看见。
- 话题标签控制在 1～2 个；不使用也可以。
- 发帖前明确希望读者做什么，并持续根据数据测试。
- Reply 是一对一交流，也可能带来有意义的互动和关注。
- 账号表达要像真实的人，而不是企业公告栏。

### 来自第三方研究和创作者经验的部分

多个来源反复出现了这些方向：

- 真实故事、过程截图、实操结论比泛泛建议更容易建立关注理由。
- 可执行内容更容易获得收藏，开放但具体的问题更容易形成自然回复。
- 私人 List 可以帮助新账号稳定找到同领域讨论，避免无限刷首页。
- 有价值的早期回复可能带来主页访问，但“越多越好”没有可靠证据。
- Buffer 对 71,000 个账号、1,880 万条 Post 的分析显示，带外链内容整体表现弱于原生文本、图片和视频。它能说明外链应谨慎测试，但不能证明每个账号都会受到固定比例的“降权”。

### 不采用的算法传说

以下说法在资料里很常见，但证据不足，不能写成规则：

- Reply 一定是 Like 的 27 倍、75 倍或其他固定倍数。
- Premium 一定得到 2～4 倍曝光。
- 前 30 分钟达到某个固定互动数就一定进入更大流量池。
- 每天必须发布 3～5 条、10 条甚至 25 条。
- 把链接放第一条回复就一定不会影响分发。

算法权重会变化，而且第三方营销工具很喜欢用精确数字制造确定感。执行时只保留方向，不迷信倍数。

## “去大 V 评论区截流”到底该怎么理解

这件事有效的部分不是“截胡”，而是借助已有公共讨论展示你的判断能力。

一个好的 Reply 应该同时满足：

```text
即使脱离原帖，也有一小段独立价值
与自己的账号主题一致
补充原帖，而不是复述原帖
让看到它的人有理由点进主页
```

### 四种可持续回复

1. **补充案例**：分享自己亲自做过的相关实验或踩坑。
2. **补充边界**：指出这个判断在什么情况下不成立。
3. **补充方法**：给出一个原帖没有展开的执行步骤。
4. **提出具体问题**：问一个能把讨论继续向前推进的问题。

示例：

```text
原帖：复杂项目应该先写完整 spec。

差的回复：学到了，太有用了！

可用回复：我最近反而踩了另一个坑：探索期太早写完整 spec，Agent 会把还没验证的假设固化下来。现在我会先用 3 个问题把方向问清，确认要做后再进入正式 spec。
```

### 不能做什么

X 官方规则明确反对：

- 对大量账号发布重复、未经请求的回复。
- 自动根据关键词批量回复。
- 激进关注／取关，或用自动化制造关注关系。
- 批量发布重复或近似内容。
- 为了导流而与大量帖子进行不自然互动。

因此不安装自动评论、批量点赞、批量关注工具。52by 资料里推荐的“自动评论、批量多账号互动”等动作与 X 官方规则直接冲突，不进入你的工作流。

## 新账号的主页转换

回复只能带来主页访问，主页决定对方是否关注。

### 头像

沿用统一的高马尾、圆框眼镜、电脑／AI 工作形象。缩小后要能认出轮廓，不放复杂背景和小字。

### 简介

建议三行：

```text
AI 产品新人，开发做过，创业也试过
公开测试 AI Coding、Agent 工作流和真实项目
把踩坑、工具判断和可复用方法写出来
```

不需要堆“学生、产品经理、开发者、创业者、博主”等所有身份。主页需要回答的不是完整履历，而是“关注你以后会持续看到什么”。

### 置顶帖

起号前先准备一条置顶导航：

```text
我在这里公开记录三件事：

1. 用 AI Coding 把想法做成真实 Demo
2. 测试 Agent／Skill 工作流到底值不值得用
3. 从学生和产品新人的视角复盘项目与自媒体实验

我不会只转发 AI 新闻。
所有内容尽量包含：亲自试过、具体结果、适用边界。

第一篇：一句 Hi 为什么启动了整套开发流程 ↓
```

## 你的三个内容支柱

### 1. AI Coding 现场

- 今天用什么工具完成了什么。
- 哪一步比想象中贵、慢或难。
- 截图、Demo、命令和结果。

### 2. Agent／Skill 判断

- 两个工具究竟在解决什么不同问题。
- 一个工作流什么时候值得启动。
- Token、上下文、权限和维护成本。

### 3. AI 产品成长记录

- 一个想法如何变成 Demo。
- 黑客松、实习、创业和内容实验的复盘。
- 自己的判断发生了什么变化。

三类内容都围绕同一个人设：一个有开发经历、正在用真实项目训练 AI 产品能力的人。

## 30 天起号节奏

### 发布前准备

- 完成头像、简介、封面和置顶帖。
- 先准备 8～10 条种子内容，避免别人从 Reply 点进主页后只有一两条内容。
- 建三个私人 List：核心大号 20 个、同阶段创作者 30 个、潜在读者／社区 20 个。

### 第 1 周：让主页能够承接流量

每天：

- 1 条原创短帖，优先真实现场或一个明确判断。
- 5 条认真回复，控制在 20～30 分钟内。
- 回复自己收到的所有有效评论。

本周不追求爆款，只检查：陌生人点进主页后，能不能看懂你是谁、关注后能得到什么。

### 第 2 周：发布第一条主 Thread

- 发布 Superpowers Thread。
- 之后两天从 Thread 拆出 2 条单点内容：工程纪律的启动成本、四类 Skill 的任务粒度。
- 对评论里反复出现的问题逐条回答，不急着在第一帖里塞完所有信息。

### 第 3 周：建立连续剧情

- 发一次“我把文章跨平台发布后看到了什么”的复盘。
- 发一个正在做的 Demo／项目进展。
- 引用一条同领域帖子，补充自己的真实案例。

### 第 4 周：只放大有效信号

复盘过去 20～30 条内容，找出：

- 哪种开头获得更多停留和展开。
- 哪类内容带来更多主页访问。
- 哪些 Reply 带来关注，而不只是曝光。
- 读者更关心工具、过程、成本还是职业成长。

下个月只扩大表现最好的两个主题，不重新发明一套账号定位。

## 一个可持续的日常 SOP

```text
10 分钟：看私人 List，挑真正能补充的讨论
20 分钟：写 5 条有独立价值的 Reply
20～40 分钟：发布 1 条原创现场／判断
10 分钟：回应自己的评论
5 分钟：记录数据和读者问题
```

不需要全天候蹲大 V。只有当一条帖子与你的真实经验相关时，“早回复”才有意义。

## 要看的数据

曝光量不能单独判断内容是否有效。每周记录：

| 指标 | 它回答什么 |
| --- | --- |
| Impressions | 内容是否获得分发 |
| Profile visits | 这条内容有没有让人对“你”产生兴趣 |
| New follows | 主页和内容承诺是否完成转化 |
| Bookmarks | 是否具有以后还想再看的价值 |
| Replies | 是否形成真实讨论 |
| 目标读者回复 | 吸引来的是否是 AI Coding／产品／独立开发人群 |
| Reply 带来的主页访问 | 评论策略是否真的有效 |

核心漏斗：

```text
内容曝光
-> 主页访问
-> 关注
-> 再次互动
```

一条回复有 10 万曝光却没有主页访问，对起号价值很低。一条只有 2,000 曝光、但带来 30 个精准关注，反而更值得复用。

## 2026-08-08 补充：长视频发布研究

本页面向文字起号；长视频（尤其 20 分钟横版）的流量机制与发布策略，见 [[X长视频流量机制与发布策略-2026-08-08]]。核心结论：X 当前主推竖屏短视频，长视频只作主页资产，增长靠切片 + 讨论；完整视频上传需要 X Premium（Basic 档即可）。

# 自媒体复盘与改进日志

## 2026-09-07｜纯视觉产品可先用成品做最小反响测试

- **触发**：口播版已经大幅简化后，用户仍判断“直接展示一个炫酷的卡，录个视频看反响就行”。
- **观察**：当产品的核心价值能被 8--12 秒的动态成品完整呈现时，原图对照、工具解释、耗时和适用人群都会分散第一轮测试。
- **判断**：第一条只测成品吸引力；有明显播放、完播或主动追问后，再用第二条解释怎么做。这是本选题的单次实验假设，不直接提升为所有内容的通用规则。
- **改动**：新建 v3 纯成品展示执行版，v2 口播版保留为后续备选。
- **验证**：发布 48 小时后看播放、完播、点赞/收藏以及“怎么做/能否做自己或宠物”的主动追问。
- **关联**：[[../04-公众号稿件/Holo-Card-Studio-纯成品展示短视频-v3]]。

## 2026-09-07｜强视觉项目的第一版策划不要先讲技术机制

- **触发**：Holo Card Studio 首版策划先讲分层图、Blender、Three.js、许可与实测边界，用户直接反馈“我都没看懂，感觉不通俗易懂”。
- **观察**：事实审计对幕后制作必要，但把它放在选题解释和第一期口播里，会遮住最直观的观看理由：普通照片变成了会转、会闪、会翻面的卡。
- **判断**：强视觉工具的首期内容应先讲“原来是什么、现在变成什么、好不好玩、麻不麻烦、谁值得用”。技术机制作为幕后证据保留，只在观众追问教程时做第二期。
- **改动**：保留 v1 为技术备忘，新建 v2 通俗执行版，将口播压到 30--45 秒，主线改为“原图 -> 成品 -> 玩法 -> 真实成本 -> 适用人群”。
- **验证**：实测后先只试讲 v2 的前 9 秒；如果不看项目说明的人也能复述“原图变成了可操作的闪卡”，再继续录完。
- **关联**：[[../04-公众号稿件/Holo-Card-Studio-通俗短视频制作包-v2]]、[[../04-公众号稿件/Holo-Card-Studio-短视频与小红书图文制作包-v1]]。

## 2026-07-28｜知识型长视频开场先给反差，不先给课程承诺

- **触发**：四个 AI Coding Skill 长视频原开头以“这十几分钟，我想帮你解决一件事”开始，用户指出此前已提供爆款开场钩子库，当前稿没有真正落实。
- **观察**：原稿虽有痛点，但价值承诺在前、具体冲突在后，听感接近课程导语；观众尚未得到值得继续听的反差或风险。
- **判断**：本片适用“痛点场景 -> 反常识判断 -> 挑战承诺”：先给“AI 最危险的时候不是写得慢，而是十分钟做出 Demo”，再呈现第二天返工的场景，最后承诺用十几分钟讲清如何克制地使用 Skill。不得为了钩子编造数字、恐惧或热点。

- **验证**：下一次试听前 30 秒时，检查观众能否复述“为什么 AI 越快反而越危险”以及本片将解决什么。

## 2026-07-18｜教程口播不追求一镜到底，先按完整语义块录

- **触发**：Codex 换肤教程首次原片共两段（安装/换肤约 5 分 19 秒，恢复/删除约 1 分 26 秒）。原片的画面操作、鼠标引导和人像小窗清楚，但口播在“看着文章临场转述”时出现整句重启、泛指“这个东西”和重复的连接词。
- **判断**：这不是单纯的气口问题；长句边操作边组织语言才是重复来源。逐字背稿或把每个“然后”剪掉，都会让成片更僵。

- **验证**：重录开场、安装成功提示和选图三个语义块；比较是否减少“整句重启”，而不是比较是否零停顿。

## 2026-07-18：正式记忆与低频反思必须分层

- 现象：仅靠 Stop Hook + Hermes 设想无法同时满足跨会话、可审计、低成本和不污染正式内容；关闭 Zvec 后，未显式传 `--no-zvec` 仍会让 closeout 因可选能力 warning 跳过提交。
- 改进：Codex 原生 memories 只作召回，Agent Memory Vault 保存正式 Markdown，低频 Codex 只生成候选；所有 v1 搜索、prewrite 和 closeout 命令显式关闭 Zvec。
- 防重复：自动候选不得直接提升；并发 closeout 只处理当前会话 claim 的文件；后台模型不可用时保留事件，不回退昂贵模型。
- 验证：关键词召回、Agent Memory Vault 40 项测试、反思桥 8 项测试、真实候选生成、文件认领隔离和密钥扫描已通过。

用途：记录已经影响后续工作方式的成功、失败、用户纠正和待验证假设。它不是日记，也不代替每篇内容自己的复盘卡。

## 记录格式

```text
日期：
触发：哪条内容、哪个任务或哪次用户纠正
观察：实际发生了什么
判断：这说明什么，不说明什么
改动：后续流程、模板或 Skill 应如何调整
验证：下一次在哪个任务里验证
关联：相关稿件、资源卡、平台操作系统
```

# 2026-08-05：讲解型 PPT 只承载结构和关键词，不承载整篇口播

- 触发：用户提供了一份更合适的 HTML PPT 参考，并明确说明这一版 PPT 不需要 Codex 继续制作，重点是让 Codex 学会它的内容切片方式。
- 判断：优秀的讲解型 PPT 不是口播稿的缩略复制，也不是公开飞书文档的替代品。第一页用核心判断立题，第二页呈现一个实际问题，后续按口播论证节奏递进；每页只完成一个讲解动作，H1/H2 写判断锚点，正文只保留短问题、短结论、标签和卡片。
- 固化结构：核心判断 → 实际问题 → 四种返工 → 四个比较问题 → 四个 Skill 分工 → 统一案例 → 关键对照 → 组合路线 → 最终选择。不要写“今天会讲”等主持词，不把完整句群塞进页面。
- 分工：口播负责听觉解释，PPT 负责观众现场跟路，飞书负责独立阅读、对照、来源和收藏；视觉风格可复用模板，但不把模板的颜色和装饰当作永久规则。
- 当前决策：本项目这一版 PPT 以用户提供的参考方案为准，Codex 不另做并行 PPT；后续重点维护口播稿、讲解思维导图和公开飞书内容的一致性。

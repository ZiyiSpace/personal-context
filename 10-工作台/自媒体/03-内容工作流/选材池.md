## 2026-09-07｜我把自己做成了一张会闪的 3D 卡

- 状态：**高时效候选；当前只做 8--12 秒纯成品展示，不口播、不讲过程、不做图文，先测视觉反响。**
- 来源：[EverettFish/holo-card-studio](https://github.com/EverettFish/holo-card-studio)，2026-09-07 创建的 Codex Skill；当日快照约 380 stars、51 forks，无 Release 和仓库内成品 demo。
- 核心问题：一张普通照片变成“会转、会闪、还能翻面的电子卡”后，到底好不好玩，又需要花多少工夫？

### 一句话判断

第一条不做内容解释，只把卡片本身当内容：光带扫过 -> 缓慢转卡 -> 翻到背面 -> 回到最美正面。用一条很短的视频先回答“它够不够炫”，观众追问后再做制作内容。

### 为什么先做视频

- 镭射、视差、拖动和翻面都是随时间/角度变化的证据，静态卡片无法独立证明。
- “原图 0.5 秒 -> 可拖动成品”能在首屏构成反差，适合小红书和抖音的 45--60 秒竖屏。
- 图文作为第二份内容，承担六页可收藏信息：成品、交互、四层机制、交付物、真实成本、适用/不适用。

### 发布前必须补齐

1. 实际跑通一张自有素材的卡，记录首次成品时间、总时间和人工返工。
2. 测试四层对齐、中文文字、Blender 可编辑性、网页拖动/翻面/滑杆/截图和手机布局。
3. 保留一个失败或修改点，不把“三十秒看懂”误说成“三十秒生成”。
4. 公开归因 GitHub 仓库，并保留 README 标注的原始教程来源：小红书 `@乌托邦的香蕉`。

## 2026-09-07｜让自己的主页头像走出屏幕：15 秒固定机位短剧

- 状态：**候选选题，已完成原帖链路与传播反馈研究；先用自己的主页截图做一轮最小实测。**
- 类型：AI 视频、个人主页、头像角色、提示词拆解、小红书图文。
- 来源：[[../06-资源链接/津轻-个人主页头像恶作剧视频提示词]]

### 一句话判断

不要搬运原视频或只翻译长提示词。用自己的公开主页截图和有授权的头像复刻一次，把内容做成“固定场景 + 角色参考 + 分秒时间轴”的可复现实验，并公开 UI 漂移、角色不一致、文字乱码和重试成本。

### 为什么值得做

- 原帖在 2026-09-07 读取约 115.7 万浏览、4224 收藏，中文传播复述也获得约 54.9 万浏览，说明这个视觉钩子已经跨语言传播。
- 创意与个人主页天然相关，换成自己的小红书主页后有个人化空间，不需要复制作者角色和成片。
- 15 秒内包含起因、动作升级和结尾定格，比“让头像动起来”更适合拆解提示词结构。
- 外部复刻已经暴露真实变量：有人使用 Genspark / Seedance 2.5，有人用 Grok 分段生成；工具名不是确定答案，正好可以用自己的实测补上证据。

### 发布前最小实测

1. 使用自己的公开小红书主页截图，先隐藏私信、通知、未公开数据和不需要出现的身份信息。
2. 使用自己制作或明确获授权的头像角色；不下载原作者头像和视频当生成素材。
3. 首轮只选一个可用视频模型，按 15 秒时间轴生成；记录模型/版本、输入素材、次数、耗时、成本和失败点。
4. 验收四项：背景 UI 是否漂移、角色是否一致、手脚/道具是否异常、最后文字是否准确。
5. 失败时先把复杂动作拆段，再考虑 CapCut 等后期；在内容中明确标注哪些是模型生成、哪些是人工修正。

### 小红书拆法

- 轮播先讲“原帖 vs 提示词回复”的来源关系，再讲 3 个可控输入、15 秒动作结构、自己的复刻步骤和失败边界。
- 真正的传播主素材应是自己的复刻视频；图文负责让读者看懂怎么做、为什么容易失败。

## 2026-09-04｜同一张照片，交给不同视觉 Skill 会发生什么？

- 状态：**候选选题，建议先做最小视觉实验，再决定是否录制/成稿。**
- 类型：AI 视觉 Skill、设计判断、图像生成实测、跨平台内容。
- 核心问题：同一张真实照片交给不同设计 Skill，变化的究竟是“滤镜”，还是主体取舍、信息密度、文字角色和图文关系？

### 一句话判断

不要做“我安装了 8 个审美 Skill”的工具清单。把这期做成一次可复现的对照实验：同一张有授权的真实照片，先跑 `Mono Color` 和已安装的 `Yingzao`，再用其他候选做快速谱系对照；最后给出“什么内容该用什么视觉转译”的选择规则。

### 为什么值得做

- 有明确现场：同一输入却得到不同结果，观众能直接看见设计判断，而不是听抽象形容词。
- 有机制可讲：`Mono Color` 偏单色/双色编辑印刷与信息层级；`Yingzao` 偏真实照片、主体身份保护、中文展示字和在地语境。
- 有边界可建立：生成图负责视觉气氛和观点锚点；准确中文、代码、步骤、数据、产品界面仍交给 HTML/CSS、真实截图和后期排版。
- 可自然形成系列：第一期讲“照片如何被重新判断”，后续再讲网页审美 Skill 或视频动效 Skill，不把不同类型资源硬塞在一条内容里。

### 首轮最小实验（发布前完成）

1. 选 1 张自己拍摄或明确获授权的照片，主体应有可识别的建筑/活动/物件，不含隐私和未公开信息。
2. 使用同一份 brief、同一画幅目标，分别测试 `Mono Color` 与 `Yingzao`；记录输入、版本、是否调用远端图像模型和人工修改。
3. 其他候选只做缩略对照：`GC Minimal`、`Pixel Style`、`Photo Abstract`、`Photo Relic`、`Gathered Scenes`。不把未安装 Skill 的仓库描述冒充本机实测。
4. 验收只看三项：主体/照片证据是否被改坏、手机缩略图是否能看懂主信息、从初稿到可发布图需要多少人工修图。
5. 若照片涉及商业化账号、广告、赞助或带货，优先排除非商业许可的候选（尤其 `Gathered Scenes`、`Photo Abstract`）；示例图和他人照片不直接复用。

### 推荐叙事结构（母内容）

```text
开场：我以为 Skill 只是换滤镜，结果同一张照片被做成两种设计判断
-> 统一输入与实验规则
-> Mono Color：先建立印刷系统、标题层级和信息秩序
-> Yingzao：先保护真实主体，再让照片进入中文编辑海报
-> 快速谱系：留白 / 网点 / 抽象面板 / 纸本记忆 / 场景蒸馏
-> 选择卡：事实信息、情绪扉页、真实现场、商业化内容分别怎么选
-> 边界：生成视觉不等于准确排版，也不等于获得素材商用权
```

### 跨平台拆法

- 公众号：写“设计判断对照实验”，放原图、两张主结果、验收表和许可/事实边界；标题候选：`同一张照片，交给两个 AI 视觉 Skill，为什么像换了两位设计师？`。
- 小红书：封面先给结论，4–7 页依次放原图、Mono Color、Yingzao、快速谱系、选择规则；每页只回答一个问题，不用生成图承载长中文。
- 视频号 / 抖音：60–120 秒，镜头顺序固定为“原图 → 双结果 → 一句话机制 → 选择规则”；不要逐个念仓库 README。
- X：发一条带图短帖或 thread，强调“Skill 的差异不在滤镜，而在它替你做了哪些取舍”，附原始仓库链接和实测局限。

### 不做什么

- 不宣称“最全”“最好看”或模型稳定生成正确中文。
- 不把 `Hallmark`、`Refero Styles`、`MotionSites` 等网页设计资源和本期照片海报实验混成一个大合集；它们留作后续“AI Coding 如何做出有审美的网站”选题。
- 不把已登记候选写成已安装、已实测；`Yingzao` 已安装，`Mono Color` 等仍需按隔离目录小样验证。

## 2026-08-20｜AI + 垂直行业第一期：老师缺的不是 AI 助手，是一套不用替 AI 擦屁股的工作流

- 状态：**本周选题，已完成第一轮调研；先电话访谈，再用 WorkBuddy 做一条教师 FDE 最小工作流，实测通过后录制教程。**
- 类型：AI + 垂直行业、教育、教师 FDE、WorkBuddy 工作流、知识库与生成式 AI。
- 主问题：当教师认为“搜题和出知识点低价值、AI 出题也不专业”，且备课真正耗在“这一节到底讲什么、怎么讲学生才懂、PPT 怎样有趣又简单”时，如何用 WorkBuddy 做一条不替代教师判断的教学设计工作流？

### 一句话判断

不要写“ima 不行，所以教师 AI 是蓝海”。更准确的说法是：ima 当前已有教师、班级教学和学校教务的官方场景，但搜题、知识点生成和无约束出题并不是教师认可的专业价值；更大的摩擦是从教材到“学生能听懂的一节课”的教学设计。WorkBuddy 可作为资料读取、讲解路径比较、课堂/PPT 骨架、审核和文件交付的工作流宿主。真正要验证的是：它能否让老师少做真实、重复的事，同时保留教师对讲法、班级和最终评价的判断。

### 推荐标题与开场

- 首选标题：**老师最累的不是做 PPT，是想清楚这一节课到底怎么讲**
- 备选：**我没让 AI 替老师备课，而是让它先给出 3 种讲法**
- 开场：先承认“AI 搜题和出题不够专业”，再抛出表姐真实痛点：“这节课到底讲什么、怎么讲才有逻辑又让学生懂？”展示 WorkBuddy 先把课标、教材和旧课件组织成几条讲解路径，老师再决定哪条能进课堂。

### 内容判断与边界

- 使用“基于自有材料搭建的知识库助手”，不要说“自创 AI”，除非有模型训练、工作流编排或系统接入的证据。
- 不把 ima 称为“老掉牙”或“没有教师场景”：腾讯当前公开材料确有教师用例，且腾讯软件中心页面 2026-08-04 仍列版本更新。
- 不攻击具体老师。演讲热度可说明培训/信心需求，不能代替教师留存、学习效果或学校采购证据。
- 中国政策将 AI 助力教育、教师队伍建设、师生数字素养与数据/算法/伦理安全放在一起；不能写成“国家要求所有老师现在用 AI”。

### 建议实测

已确认第一任务是备课。用公开课标/教材 + 旧教案/课件 + 教案/PPT 模板，经 WorkBuddy 输出“核心理解、讲解路径、课堂节奏、逐页 PPT 骨架和教师待确认项”；记录资料准备成本、首稿时间、教师对讲法/PPT 的删改处、课标/事实错误和最终是否愿意带进课堂。第二轮再找 3-5 位不同学段/学科教师各试一周，只记录使用频次、真实节省时间、人工复核处和放弃原因。

## 2026-08-14｜下一篇确定：DeepSeek Harness 到底是不是另一个“全家桶 Agent”？

- 状态，**确定为下一篇，先研究与最小实测，暂不碰正式业务项目。**
- 类型，AI Coding、Agent 框架、Skill 生态、开发者工具。
- 官方项目：[deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)，2026-08-13 发布开发者预览；2026-08-14 复核为约 58,251 stars、4,789 forks、MIT。官方 README 明确标为快速迭代阶段，未来会有破坏兼容性的变更。
- 实际入口：官方给出的最短运行命令是 `npx @deepseek-ai/dsh web`，默认启动本机 `127.0.0.1:3080` Web UI；根包版本为 `0.1.0-rc.5`，要求 Node.js `^22.19.0 || >=24.0.0`。

### 不做“速通”，要回答什么

不是重复“DeepSeek 也出了一个 Codex”。真正值得亲手研究的是：Harness 把模型、工具、Skill、会话、沙箱、文件系统、循环、编排和 UI 都定义成插件后，使用者究竟获得了什么；第一次启动和改造时，又需要为这种自由付出多少配置、兼容性与安全成本。

它和上一篇“Skill 应按任务粒度选择”形成自然续篇：前一篇讲**什么时候需要一条 Skill**，这一篇讲**当 Skill、工具和运行时都能换时，谁来负责把它们组织成一个 Agent**。

### 建议标题与开场

- 首选标题：**DeepSeek 也出了个 Agent：我没急着装，只想先搞懂它和 Skill 到底差在哪**
- 短视频标题：**一夜 5 万 Star 的 DeepSeek Harness，先别急着装**
- 开场冲突：昨天大家还在往 Agent 里塞 Skill，今天 DeepSeek 直接说“所有东西都是插件”。听上去很自由，但我的第一个问题不是“能不能跑”，而是“出了问题时，到底该改 Skill、换工具，还是换整个运行时”。

### 第一轮只验证三件事

1. **能否启动**：使用官方 `npx` 入口在独立目录启动 Web UI，记录 Node 环境、首次启动耗时、依赖下载与报错，不使用社区桌面壳或一键安装包。
2. **插件边界**：只拆一条小任务，分别确认模型、工具、Skill/指令、会话与循环在哪一层配置；不把“插件很多”误写成“普通人都需要自己写插件”。
3. **可控性**：运行一个只读、可撤销的本地任务，观察工具权限、文件访问、日志和停止方式。API Key、真实项目目录、账号 Cookie 与私密资料不进入首轮测试。

### 这篇该给出的选择规则

- 只是要一个能完成编码任务的 Agent：暂时不因“插件化”迁移，先看现有 Codex/Claude Code 是否已经满足。
- 已有明确的工具、模型或工作流要替换，且能承受开发者预览的不兼容：Harness 才值得投入第二轮。
- 想先做内容：第一轮的失败记录、配置复杂度和“Skill 与 Harness 的职责差异”本身就是比安装教程更有价值的素材。

### 热度与风险判断

AI HOT 记录显示，此次官方发布于 2026-08-13 进入高热度事件。GitHub 同日已出现大量非官方插件目录、桌面壳、Docker 包装和“一键安装”项目；首轮只使用 `deepseek-ai` 官方仓库和 npm 包，避免把社区包装当作官方能力。开发者预览、Node 版本要求和破坏兼容性也应在标题与正文中讲清楚。

社区首日反馈的有效矛盾已经出现：开发者赞赏组件可替换、事件日志与 UI；实际使用者也反馈插件/Skill 入口和文档不直观、子代理问题、速度及 token 成本。完整来源和局限见 [[../06-资源链接/DeepSeek-Harness-社区反馈-2026-08-14]]；这些是文章验证假设，不能代替本机结果。

### 一句话选材判断

可以做一期真正的对比实测，用同一份 30 秒竖屏知识视频脚本，分别让 Codex 驱动 HyperFrames 和 Remotion 出片，记录搭建时间、渲染时间、报错、人工修改量和最终效果，再给出普通创作者的选择规则。

### 为什么值得做

原文把 Codex、HyperFrames、Remotion 和自动化出片放在了一条链路里，给出了安装、提示词、渲染和修改思路。这个题目同时具备视觉效果、真实操作和明确选择问题，适合做视频主内容，再拆成公众号教程和 X Thread。

对我们的价值不在「一键月入」或「日产 30 条」，而在下面这个真实问题。

```text
一个不会手动写视频代码的创作者
能不能只用自然语言
让 Codex 稳定做出一条可以发布的程序化视频
```

### 推荐实测方案

固定一份 30 秒竖屏脚本，内容可以用「Codex 换皮肤的 3 个步骤」或其他已经完成的短内容，避免选题质量干扰工具比较。

HyperFrames 和 Remotion 使用相同的画面要求。

- 1080 × 1920
- 30 秒
- 4 个场景
- 深色背景
- 标题入场、步骤卡片、进度条、底部字幕
- 同一套配音和素材

实测记录五项。

1. 从空文件夹到看到第一个预览用了多久
2. 安装和渲染出现了多少次报错
3. Codex 能否自己定位并修复错误
4. 成片需要人工修改多少处
5. 第二次替换文案重新出片需要多久

### 文章或视频的核心问题

- HyperFrames 的 HTML、CSS、GSAP 路线是否真的更容易让 Codex 一次写对
- Remotion 的 React 组件和时间轴是否更适合长期维护栏目模板
- 两者在中文配音、字幕对齐、竖屏适配和渲染速度上的差距
- 普通创作者应该选择更快的首次出片，还是更稳定的长期复用

### 暂定选择规则

- 想快速做动态知识卡片或验证视觉想法，优先测试 HyperFrames
- 想做固定栏目、批量替换数据和长期维护模板，优先测试 Remotion
- 只是做讲书、口播或普通图文混剪，先比较剪映，不默认上程序化视频工具

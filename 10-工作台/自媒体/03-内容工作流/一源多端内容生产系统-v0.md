# 一源多端内容生产系统 v0

定位：用海外/X/GitHub 等一手信息做选题雷达，但只发布经过验证、转译并注入自身判断的内容。目标不是“自动搬运”，而是稳定产出可被不同平台重新表达的内容资产。

这套系统以 [[../06-资源链接/Fred-一源多端内容系统观点]] 为触发，但已经去掉无法核验的收入叙事和“搬运”逻辑。

## 总链路

```text
信息雷达
-> 证据包
-> 个人摩擦 / 测试 / 判断
-> 母内容
-> 平台编辑
-> 发布与复盘
-> 更新雷达和判断库
```

## 每一层要交付什么

| 层 | 输入 | 必须产物 | 不做什么 |
| --- | --- | --- | --- |
| 信息雷达 | X、GitHub、产品发布、真实使用摩擦 | 原链接、作者、日期、为何值得看 | 不把转发当选题 |
| 证据包 | 原帖、官方文档、仓库、实测 | 事实、观点、来源、待证项、外链 | 不把作者自述当事实 |
| 个人判断 | 你的开发经历、成本、失败、测试 | 一句反直觉或可执行判断 | 不写没有现场的万能工具介绍 |
| 母内容 | 证据包与判断 | 可被引用的完整中文稿 | 不按某个平台模板硬凑 |
| 平台编辑 | 母内容 | 对应平台的重新叙事、视觉与互动动作 | 不一键复制粘贴 |
| 复盘 | 发布数据与评论 | 哪个判断/包装值得保留的记录 | 不用一次数据宣布规律 |

## 你现在真正要跑的内容引擎

主线是 [[../05-Codex中文系统教程/README|Codex 中文系统教程]]，不是一篇篇彼此孤立的工具测评。这个系列持续回答：一个真实用户如何理解、安装、使用、扩展、排错并判断 Codex；每个教程都要有真实操作、可复核来源和自己的判断。

并行但次级的栏目是 AI Coding 工具现场：只有当你真的遇到成本、权限、工作流或项目落地的摩擦时，才写成案例。Superpowers 属于已经完成的历史案例，不再承担“试跑工作流”的角色。

```text
Codex 系列问题 / 新的真实 AI Coding 摩擦
-> X、GitHub、官方文档与本机实测
-> 来源卡与证据包
-> 教程母内容或案例母内容
-> 公众号、图文、X、视频各自编辑
-> 反馈回写进 Codex 教程的问题池与选题池
```

## 内容引擎的实际版本

### 1. 信息雷达

你已经在做：X 链接、GitHub 项目、官方文档、Codex 版本变化和本机真实操作。每个链接都先进入 `自媒体/06-资源链接/`；与 Codex 具体章节有关的证据，再进入 `自媒体/05-Codex中文系统教程/90-资料与证据/`。

### 2. 证据包

每个要写的题，先回答：

```text
它发生了什么：
为什么我会在意：
我亲自遇到/测试到什么：
哪些是官方事实，哪些只是作者观点：
我最终给读者的判断：
什么还不能下结论：
```

### 3. 母内容

教程或公众号承担完整叙事：从真实任务或摩擦进入，说明机制和选择标准，保留条件与边界。它不是所有平台的“原封不动长文”，而是事实与观点最完整的版本。

### 4. 平台编辑

| 平台 | 从母内容取什么 | 不该做什么 |
| --- | --- | --- |
| 公众号 | 完整现场、机制、证据和取舍 | 写成工具清单或 README 翻译 |
| 小红书 | 一个判断 + 4 到 7 页可独立阅读的图文 | 直接缩短公众号，或让封面替代内容 |
| X | 一个短判断、关键证据与原始链接 | 伪装成独家或复制他人原文 |
| 视频 | 冲突开场、口播判断、必要的画面证据 | 先做泛 PPT，再找观点填进去 |

视频的具体执行继续由另一条对话负责；本文件只定义它从哪里取内容。

## 系列如何持续，而不是每次重新想题

1. 从 Codex 用户问题地图、版本变更、官方案例、X/GitHub 信号或你自己正在做的任务中，拿到一个具体问题。
2. 先做一轮真实操作，记录成功条件、失败点、时间成本、截图和原始链接。
3. 写进 Codex 系列对应章节，或写成一篇 AI Coding 现场案例；两类内容都必须有“什么情况下别照做”。
4. 再把同一个判断改造成不同平台版本：公众号保留完整过程，小红书只讲一个可收藏的判断，X 带原始来源和短观点，视频只录一个具体任务的开始、卡点和结果。
5. 发布后的提问、误解和复现失败，回写进用户问题池、章节勘误或下一篇选题，而不是只记播放量。

这才叫持续地跑：不是反复找新爆点，而是 Codex 系列本身越写越厚、越用越可靠。

## 边界

- 永远保留原始来源，尊重版权与平台规则；引用、截图和二次创作要满足合理使用、授权和平台要求。
- AI 只加速整理、改写、排版和候选生成；事实核验、个人判断和发布由人负责。
- 先完成一个完整闭环，再增加自动化、更多平台或更多 Skill。

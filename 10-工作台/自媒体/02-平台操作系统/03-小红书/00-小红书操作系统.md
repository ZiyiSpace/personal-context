# 小红书操作系统

定位：把“开发者亲自遇到的 AI 工具摩擦、验证与判断”改造成一眼能懂、愿意收藏的图文笔记。不是把公众号缩短，也不把每个工具做成夸张的爆款承诺。

## 当前入口

1. [[01-封面提示词工作流-狗哥笔记]]：把封面从随机生图改成可复用的输入 brief。
2. [[02-Skill地图]]：目前已有的生成、排版、发布前复核能力，以及各自边界。
3. [[../../06-资源链接/狗哥笔记-小红书封面提示词工作流]]：这条 X 帖子的客观资源卡与核验状态。
4. [[../../06-资源链接/Yuwen-Publish-Precheck-国内自媒体发布前审查]]：发布前人工复核候选。

## 主流程 v0

```text
真实摩擦或已写好的母内容
-> 只留下一个读者最关心的判断
-> 选图文结构（封面 + 4 到 7 页）
-> 每页只回答一个问题
-> 封面 brief 与素材盘点
-> HTML 文字卡 / 必要的角色或人物图
-> 手机端读字与事实核对
-> 发布前语境复核
-> 记录标题、封面、收藏评论和下一次假设
```

## 三条纪律

- 公众号的叙事可以保留，但小红书的每一页都必须独立可读；第一屏先给判断或冲突，不做长前言。
- 信息型内容优先 HTML/CSS 卡片和真实截图；AI 生图只承担人物、场景和情绪，不负责虚构 UI、数据或大量中文。
- Skill 只能整理输入、生成候选、做检查；选题、封面最终取舍和发布按钮仍由人把关。

## 当前边界

- 这只是 v0：先能稳定把公众号或真实经历转成一条图文笔记，再谈批量生产与自动发布。
- “爆款封面”“数据驱动”“人脸一致性”均需真实内容对照验证，不能作为承诺写进账号表达。
- 具体发布规则、商业合作声明和 AI 标识以平台当期页面与官方规则为准；资源卡只做辅助复核。
